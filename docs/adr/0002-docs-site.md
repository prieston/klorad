# ADR-0002: apps/docs on Fumadocs, not Docusaurus

Status: proposed (NEEDS TEO APPROVAL, board item, gate "Needs my approval"). Written 29 September 2026.

## Context

`apps/docs` is the first documentation site for the SDK: a TypeDoc-generated API reference over
`packages/api/src/index.ts`, a Concepts section for the three thesis layers, and the "Building a
Klorad app" guide as the getting started page. It needs to live in the same monorepo as six other
Next.js 15 App Router apps and pass the same `pnpm check` gate.

Docusaurus was the original spec. A prior agent run found it would be the one non-Next.js app in
`apps/`, its own build/lint/routing system in a monorepo that already standardised on Next, which
runs against the root `CLAUDE.md` rule to prefer the platform already in use. Teo decided
(25 September 2026, board item 3230175493) to scaffold with **Fumadocs** instead: a Next-based
docs framework (`fumadocs-core` + `fumadocs-ui`), so `apps/docs` is one more Next app with its own
`pnpm --filter` build/lint/typecheck, not a second toolchain.

## Decision

- `apps/docs`: Next.js 15 App Router, TypeScript strict, matching the rest of the workspace.
- `fumadocs-core` and `fumadocs-ui` pinned to `~15.7.0`. Their next major line (16.x) requires
  Next 16; this workspace is pinned to Next `^15.1.9` (root `package.json` override), so 15.7 is
  the newest line that still fits.
- `fumadocs-mdx` `^11.9.0` for the MDX content pipeline (`source.config.ts`, `content/docs/**`,
  `lib/source.ts`); it is the standard companion package for `fumadocs-core`, not a separate
  framework choice, and its own peer range (`^14.0.0 || ^15.0.0`) matches the pin above.
- **Not `fumadocs-typescript`.** The board spec asked for "TypeDoc reference through
  fumadocs-typescript". Verified against a real install: `fumadocs-typescript@5.0.0` is the only
  line whose declared peer range includes `fumadocs-core@^15.7.0`, but its own build imports a
  `fumadocs-core` subpath (`fumadocs-core/mdx-plugins/remark-gfm`) that only exists in
  `fumadocs-core@16`'s export map, so it throws `ERR_PACKAGE_PATH_NOT_EXPORTED` at import time
  against the pinned 15.7 line. It is also not a TypeDoc wrapper: its `generateDocumentation` API
  is a `ts-morph`-based single-type table generator for inline "Auto Type Table" use in MDX, not a
  whole-module reference walker. The reference is generated with `typedoc` directly instead
  (`apps/docs/scripts/lib/reference.mjs`): `Application.bootstrapWithPlugins` over
  `packages/api/src/index.ts`, walking `project.children` for name, kind and JSDoc summary, one
  generated Markdown table, source-linked back to GitHub (TypeDoc resolves the git remote and
  commit on its own). `fumadocs-typescript` can come back once the workspace moves to
  `fumadocs-core@16`/Next 16, for its actual use case (inline type tables on the Concepts pages).
- **Tailwind v4 for this app only.** `fumadocs-ui@~15.7`'s own component styling ships as Tailwind
  v4 CSS (`@theme`/`@plugin`/`@source` at-rules in `fumadocs-ui/css/preset.css`); there is no
  v3-compatible release recent enough to pin. Every other app in the workspace is on Tailwind
  `^3.4.14` via `@klorad/design-system/tailwind-preset`. `apps/docs` does not use that preset: it
  imports `@klorad/design-system/tokens.css` directly (plain CSS custom properties, framework
  agnostic) and remaps Fumadocs' `--color-fd-*` variables onto them in `app/global.css`, so the
  site is Klorad's actual palette (dark by default, the teal accent) without a JS preset that
  assumes Tailwind v3. Recorded as an intentional split in `docs/SYNCPACK-MAJORS.md` and
  `.syncpackrc.json`; it does not pull the rest of the workspace toward v4.
- Content generation, not duplication. Three files are generated by `pnpm build`/`pnpm dev`
  (`apps/docs/scripts/generate-content.mjs`) and are gitignored:
  `content/docs/index.mdx` from `docs/guides/building-a-klorad-app.md` (PR #309; not merged yet at
  the time of this PR, so this ships with an honest placeholder that resolves itself once #309
  lands, no further change needed), `content/docs/reference/index.mdx` from TypeDoc, and
  `public/llms.txt` (the guide plus the generated API map, per the board spec).
- No hero, dark mode default (`RootProvider` `theme={{ defaultTheme: "dark" }}`), sidebar: Getting
  started, Concepts (World / Access / Integration placeholders), API reference (generated).
- `apps/docs` is excluded from `size-limit` budgets (root `CLAUDE.md`: they apply to editor,
  website and admin only; this is not a product app).

## Consequences

- Two real technical findings surfaced while building this that were not visible from the spec
  alone (the `fumadocs-typescript`/core-16 conflict, the Tailwind v3/v4 split); both are worked
  around inside `apps/docs` without touching any other app, and both are reversible once their
  upstream blocker clears.
- The CI step (`pnpm --filter @klorad/docs build`) cannot be added by this PR: agents cannot edit
  `.github/workflows/*` (`.agents/CLAUDE.md`). The diff is in the PR body for a human to apply.
- `apps/docs` deploys nowhere yet; Vercel project config is a follow-up, noted in the app README,
  not done here.
